Completion assessment and first real-training roadmap

A repository-specific review of what already works, what still prevents a credible educational release, and the shortest route to a real binary-classification experiment.

Reviewed 26 August 2026 · Java / Gradle · all tracked source, tests, build files, history, README, and demo inspected

Bottom line

The mathematical core is viable; the project does not need a wholesale rewrite before it learns a real problem. Dense forward propagation, nonlinear backpropagation, per-example SGD, shape checks, and an atomic trainStep are present. A focused numerical check matched finite differences to 6.8 × 10−11, and a deterministic XOR probe trained from loss 0.745953 to 0.000507 with 4/4 correct predictions.

What is missing is mostly the engineering around that core: a reproducible random source, a green and portable build, stable edge-case math, a dataset/training/evaluation pipeline, end-to-end tests, a usable example, and removal of avoidable allocation hot spots. Those pieces are substantial, but they can be added incrementally around the current dense-layer design.

Scope boundary: the in-progress softmax/multiclass attempt was intentionally excluded from this assessment. It is not counted as a defect or a prerequisite. The recommended first real task uses one sigmoid output and binary cross-entropy, so no softmax work is needed.

What is already worth keeping

  • A small, understandable object model. Net → Layer → Perceptron makes the dense forward and backward passes easy to trace—valuable for an educational library.
  • Network construction and basic shape safety. The builder checks adjacent layer dimensions and the network validates training input/target dimensions.
  • Atomic single-example learning. trainStep(input, target, learningRate) performs forward, loss, backward, and update in the correct high-level order.
  • Correct mean-loss scaling. MSE, MAE, and BCE derivatives divide by output count consistently with their reported mean loss.
  • Useful deterministic parameter constructors. Explicit weights and biases make hand calculations, gradient checks, loading, and reproducible tests possible.
  • A proven nonlinear path. The focused gradient and XOR probes show that tanh, sigmoid, BCE, hidden-layer error propagation, bias updates, and repeated trainStep calls work together in normal numeric ranges.

This is enough of a foundation to finish a deliberately scoped dense-network library. GPU support, automatic differentiation, convolutional layers, and a general tensor engine are not required for an educational v1.

What still needs to be done

P0 Restore a trustworthy, portable green build.

BackpropagationTest.multiLabelOutputLayerBackprop expects -1/+1, but mean MSE over two outputs correctly produces -0.5/+0.5. Update that stale expectation. Then declare a Java toolchain/release: the source uses List.getFirst/getLast (Java 21+), while build.gradle declares no language level. Upgrade the Gradle wrapper to a version compatible with the supported runtime and add CI for the chosen JDK.

P0 Make experiments reproducible.

He initialization uses ThreadLocalRandom; biases are lazily created with Math.random() on the first forward pass. Introduce one injected RandomGenerator or seed owned by the network/build configuration. Initialize all parameters during build(), preferably with zero biases initially. A model built twice with the same seed, structure, and data order must produce the same metrics.

P0 Check in gradient and convergence tests.

The current hand-calculated tests cover only linear activations for the main backpropagation assertions. Add central finite-difference checks for every weight and bias in small nonlinear networks, covering supported activation/loss pairings. Add deterministic “loss decreases” tests for linear regression and XOR. These tests should fail loudly on non-finite values and will protect the core while trainer code is added.

P0 Stabilize sigmoid/BCE and validate numeric inputs.

The sigmoid derivative computes an exponential quotient that returns NaN for a pre-activation of -1000. Compute sigmoid stably and derive it as s × (1 − s); for a sigmoid+BCE output, a fused error signal (prediction − target) / outputCount avoids an unstable multiply/divide pair. Reject non-finite features, targets, learning rates, losses, and gradients with a useful message; validate BCE labels as binary or within [0,1].

P0 Add the missing training/data/evaluation layer.

The library has one training step, not a training workflow. Add a small DataSet abstraction, deterministic train/validation splitting, feature standardization fitted only on training data, seeded shuffling, an epoch loop, and mean-loss plus binary-accuracy reporting. Start with per-example SGD; mini-batches are not necessary for the first small dataset.

P1 Stop cloning parameters inside hot loops.

Layer.backpropagateHiddenLayer calls nextPerceptron.getWeights() inside both neuron loops, and that getter clones the full weight vector. This changes the backward pass from the expected parameter-sized work to roughly O(currentWidth² × nextWidth) copied doubles. Each perceptron also clones the same layer input into its own lastInput. Keep defensive public getters, but add internal direct indexed reads and cache one input per layer—or move layer parameters to a matrix once clarity permits.

P1 Tighten lifecycle and ownership boundaries.

The low-level public sequence allows updating twice from stale gradients; an existing test explicitly accepts that behavior. Updating before a forward pass fails through a null cached input. Prefer trainStep as the safe public mutation API, clear/consume gradient state after an update, and either make advanced methods package-private or guard their order. Return a cloned perceptron array from Layer.getPerceptrons() so callers cannot replace internal neurons.

P1 Supply initialization appropriate to supported activations.

He initialization is a reasonable ReLU default but is the only initializer. Add Xavier/Glorot for tanh and sigmoid networks, plus a fixed/constant initializer for tests. Validate initializer arguments and document recommended activation/initializer combinations.

P1 Replace the demo and repair the README.

The README example uses removed constructors/methods and does not compile against the builder API. It also advertises categorical cross-entropy that Losses does not provide. The current demo performs only a random forward pass. Replace both with one verified command that trains, reports validation metrics, and predicts a few held-out examples.

P2 Add mini-batches, optimizers, and persistence after the baseline works.

Once the first dataset trains correctly, separate gradient accumulation from parameter updates, average a mini-batch, and introduce an Optimizer boundary (SGD first, momentum/Adam later). Add a versioned model format containing layer shapes, activation identifiers, weights, biases, and preprocessing parameters. These are v1 completion items, but they should not delay the first real experiment.

Recommended first real problem

Wisconsin Diagnostic Breast Cancer: numeric binary classification

Use this as an educational benchmark, not a medical system. It is a good fit for the library because the features are numeric, the dataset is small enough for the current scalar implementation, and the target is binary—so the unfinished multiclass path is irrelevant.

30 standardized inputs→ 16 ReLU→ 8 ReLU→ 1 sigmoid→ BCE

Start simpler if useful: logistic regression (30 → 1 sigmoid) is an excellent pipeline baseline. The neural network should then beat or at least clearly improve upon a majority-class baseline on held-out data. Record the split seed and all hyperparameters.

Minimum experiment pipeline

  1. Load numeric rows and a binary label; report row count, feature count, and class balance.
  2. Perform a seeded, preferably stratified, train/validation split.
  3. Fit mean and standard deviation on training features only; transform both partitions with those training statistics.
  4. Build the network with a fixed seed and zero biases; use He weights for the ReLU layers.
  5. Shuffle training row indices from the same controlled random source each epoch and call trainStep.
  6. After every epoch, compute mean training loss, validation loss, binary accuracy, and a confusion matrix without updating parameters.
  7. Keep the best validation checkpoint or at least restore/report the best epoch, then print a few held-out predictions.
Avoid data leakage: never standardize using the full dataset before splitting. The scaler is model state and must be fitted only from the training partition, then saved alongside the network.

Implementation roadmap

Phase 0 — Lock down the core

Fix the one stale test, declare/upgrade the build toolchain, add nonlinear finite-difference tests, add deterministic XOR and linear-regression convergence tests, and add non-finite guards.

Exit: one clean command passes on a fresh checkout and CI

Phase 1 — Reproducible, stable learning

Inject a seed/random source, initialize biases during construction, add stable sigmoid and sigmoid+BCE handling, add Xavier and constant initializers, and test identical-seed behavior.

Exit: repeated runs produce identical losses and parameters

Phase 2 — Dataset and trainer

Add DataSet, a simple CSV loader, StandardScaler, deterministic/stratified split and shuffle utilities, Trainer, TrainingConfig, and epoch metrics. Keep storage as primitive arrays and SGD as the only optimizer initially.

Exit: any numeric binary CSV can be trained without a handwritten loop

Phase 3 — First real result

Add the breast-cancer example, dataset acquisition instructions or a small checked-in fixture, baseline comparison, validation reporting, and reproducible output in the README. Tune only after correctness is visible.

Exit: one documented command trains and reports held-out metrics

Phase 4 — Scale and release

Remove hot-path cloning, introduce gradient accumulation and mini-batch SGD, add model/scaler persistence, make the API ownership-safe, publish Javadocs, and tag a deliberately scoped 0.1.0 release.

Exit: a saved model reloads with identical predictions

Later — Broaden only when a use case demands it

Add momentum/Adam, regularization, early stopping, multiclass output, and larger image examples one at a time with gradient and convergence coverage. Convolutions, tensors, GPU execution, and autodiff are separate projects—not prerequisites for finishing this dense educational library.

Definition of “finished” for version 0.1

  • A fresh checkout builds and tests with one documented Gradle command on the declared JDK.
  • All supported activation/loss combinations have finite-difference coverage at weights and biases.
  • Fixed seed + fixed data order gives identical initialization, epoch metrics, and final predictions.
  • Invalid shapes, non-finite values, invalid labels, and incorrect training lifecycle calls fail clearly.
  • A generic numeric binary dataset can be split, standardized, trained, and evaluated through library APIs.
  • The real example reports training and validation loss, class balance, accuracy, confusion counts, and hyperparameters.
  • The real example beats the recorded majority baseline and shows no unexplained NaN/infinite values.
  • A saved model plus scaler reloads with predictions equal within a documented tolerance.
  • The README compiles, matches the source, states the supported scope, and does not advertise unfinished features.
  • No public operation silently reuses stale gradients or exposes replaceable internal arrays.
