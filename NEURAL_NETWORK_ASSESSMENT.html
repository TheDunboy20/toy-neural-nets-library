Toy Neural Nets Library

Independent code review: usability, correctness, learning value, and the path to an MNIST-capable implementation.

Repository state reviewed 29 July 2026 · Java / Gradle · source and tests inspected; clean build executed

Bottom line

This is a promising educational MLP core, not yet an MNIST-ready library. The repository correctly expresses the central idea of a dense neural network—weighted sums, activations, reverse error propagation, and parameter updates—and its small deterministic tests pass. It is roughly 20–30% of the way to a minimal, reproducible MNIST learning project, and under 10% of the way to a generally usable neural-network library. The remaining work is concentrated in a few foundational pieces rather than cosmetic features.

A handwritten training loop could technically feed MNIST pixels through the current API, using ten sigmoid outputs and one-hot targets. I would not call that a sound MNIST solution: there is no softmax/categorical cross-entropy, no dataset or epoch pipeline, no batching, and the current internal defensive copying makes a normal 784→hidden-layer network prohibitively allocation-heavy.

What is already working

  • Dense layers, a builder, ReLU/sigmoid/tanh/linear activations, MSE/MAE/BCE losses, and He initialization are present.
  • The reverse pass calculates all error signals before parameters are updated, which is the right high-level ordering for per-example SGD.
  • The tests use fixed parameters to verify forward values, hidden/output error signals, and one update step. A clean sh gradlew clean test run succeeded: 14 tests, 0 failures.
  • Explicitly parameterized layers make deterministic examples and future gradient checks straightforward.

That is real progress. The project has moved beyond a collection of formulas: it has a coherent feed-forward computation graph and a working learning-step substrate for a small, single-example dense network.

Material gaps and risks

P0 No multiclass classification path.

MNIST has ten mutually exclusive classes. There is no softmax activation and no categorical cross-entropy (CCE), despite the README listing CCE. Ten independent sigmoid+BCE outputs are a workaround, not the conventional or most stable formulation. Add a numerically stable logits→softmax→cross-entropy path with the fused gradient p − y.

P0 No training or data pipeline.

The library exposes forward, backpropagate, and updateWeightsAndBiases, but has no trainStep, epochs, batches, shuffle, MNIST IDX reader, normalization, one-hot encoding, accuracy calculation, validation split, or example that learns anything. A user must invent the most error-prone workflow themselves.

P0 Backpropagation allocates far too much for MNIST.

Layer.backpropagateHiddenLayer calls nextPerceptron.getWeights() inside its inner loop. That getter clones the entire weight array. For just a 784→128 connection, backpropagating one preceding layer can clone roughly 784 × 128 arrays of length 784: about 630 MB of raw double payload per example, before array overhead. Preserve public immutability, but use an internal non-copying accessor or store parameters in contiguous matrices.

P1 Loss values and gradients disagree for multiple outputs.

MSE and BCE report the mean loss across output elements, but their derivatives omit division by the output count. With one output the tests cannot reveal it; with ten MNIST outputs, the reported objective and applied gradient differ by a factor of ten. Either return a sum or scale the derivative consistently.

P1 Model structure is not validated end-to-end.

Construction checks only that a loss exists and at least one layer was added. It does not check that each layer’s weightsNumber matches the previous layer’s output size, so malformed networks build and fail later during a forward pass. The input size is also not a property of Net.

P1 The lifecycle permits stale or missing gradients.

Calling update twice after one backpropagation repeats an old gradient; calling backpropagation before forward can lead to null cached input during update. The existing sequential-update test explicitly accepts repeated stale-gradient updates. Offer one atomic trainStep(input, target, learningRate) first; keep lower-level operations only as advanced APIs with state checks.

P1 Experiments cannot be reproduced.

He weights use ThreadLocalRandom and biases use Math.random(); neither accepts a seed. There is no model save/load. Learning results cannot be reliably compared or resumed.

P2 Design and hygiene issues.

A Layer can claim one activation while its explicit perceptrons use another; getters expose mutable perceptron arrays; validation uses generic exceptions and one input error prints to standard output; and the build does not declare a Java toolchain/release even though List.getLast() requires Java 21+.

Smallest credible MNIST milestone

  1. Make the core trustworthy. Define an input size; validate every adjacent shape and target; make one safe trainStep; correct mean-loss gradients; add numerical-gradient and XOR/convergence tests.
  2. Add the MNIST objective. Implement stable softmax plus categorical cross-entropy, one-hot labels, argmax, and accuracy. Keep logits separate from activation values where useful.
  3. Make it feasible. Replace per-perceptron copying in the hot path with matrix/array operations or at least internal direct reads; accumulate and average mini-batch gradients instead of mutating on every example.
  4. Deliver a reproducible example. Add an IDX reader, [0,1] pixel normalization, deterministic seed, train/test reporting, and a runnable 784→128→10 example that records epoch loss and accuracy.
  5. Then broaden the library. Add Xavier initialization (for tanh/sigmoid), optimizers, model persistence, regularization, progress callbacks, documentation, and CI. Do these after the MNIST baseline is proven.

Success criterion for that milestone: a clean checkout can run one documented command, train deterministically, show steadily decreasing training loss, and report held-out MNIST accuracy. A small dense baseline should be judged first for correctness and reproducibility—not for matching modern CNN performance.

Repository-specific documentation corrections

  • The README sample no longer compiles: it uses new Net(Losses.MSE(), 0.001) and net.addLayer(...), while the current source uses new Net.Builder().
  • The README claims categorical cross-entropy, but Losses exposes only BCE, MAE, and MSE.
  • The README should state that the current API is single-example SGD primitives, rather than suggesting a complete training mechanism.
